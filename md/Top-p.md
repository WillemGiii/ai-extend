### Top-p：控制候選 Token 的取樣範圍

模型會先把可能接續的 Token 按機率由高到低排列，再從最前面開始累加，直到達到 Top-p 設定的門檻，只從這一組候選裡抽選

`top_p` 也是常見的模型生成參數

它使用 Nucleus Sampling（核心取樣）的概念，根據候選 Token 的累積機率來決定取樣範圍

可以簡單理解為：

> 模型在選擇下一個 Token 時，優先考慮累積機率達到指定門檻的一組候選 Token
> 

當 Top-p 較小時，候選範圍通常比較集中

當 Top-p 較大時，模型通常會考慮更廣泛的候選 Token

由於 Temperature 與 Top-p 都會影響生成結果的變化程度，因此初學者在實驗時，可以先固定其中一個，只調整另一個，方便觀察差異

**用實際例子解釋「累積機率」**

假設輸入：

> 今天的天氣很＿＿
> 

模型算出的下一個 Token 機率如下。這些數字是教學假設：

| 候選 Token | 個別機率 | 由上往下累積的機率 |
| --- | --- | --- |
| 好 | 40% | 40% |
| 熱 | 25% | 65% |
| 冷 | 15% | 80% |
| 舒服 | 10% | 90% |
| 糟 | 6% | 96% |
| 怪 | 4% | 100% |

不同 Top-p 設定，會得到不同的候選範圍：

| Top-p | 保留的候選 Token | 原因 |
| --- | --- | --- |
| `0.5` | 好、熱 | 第一個只有 40%，加入第二個後達到 65%，才跨過 50% 門檻 |
| `0.8` | 好、熱、冷 | 累積機率達到 80% |
| `0.9` | 好、熱、冷、舒服 | 累積機率達到 90% |
| `1.0` | 全部候選 | 不透過 Top-p 排除候選 |

**重點：Top-p 是機率門檻，不是候選數量的百分比**

例如 `top_p = 0.5`，不是留下「一半數量的 Token」，也不是只留下「個別機率大於 50% 的 Token」

**3. 保留下來後，並不是每個候選都一樣容易被選中**

以 `top_p = 0.8` 為例，保留：

- 好：原本 40%
- 熱：原本 25%
- 冷：原本 15%

這三個機率合計是 80%。取樣時，會將保留的機率重新正規化，讓總和變成 100%：

| 保留的 Token | 重新計算的機率 |
| --- | --- |
| 好 | 40 ÷ 80 = 50% |
| 熱 | 25 ÷ 80 = 31.25% |
| 冷 | 15 ÷ 80 = 18.75% |

因此，模型仍可能選到「冷」，但選到「好」的機會較高

> Top-p 先決定「誰可以參加抽選」，再依照保留下來的機率抽選，不是直接選第一名
> 

**4. 跟 Temperature 差在哪裡？**

| 參數 | 主要作用 | 教學說法 |
| --- | --- | --- |
| Temperature | 調整機率分布，使高低機率的差距變大或變小 | 調整各候選被抽中的機會 |
| Top-p | 按累積機率保留候選範圍 | 決定哪些候選可以參加抽選 |

補充一個關鍵：**Top-p 每產生一個 Token 都會重新套用，候選數量並不固定。** 如果模型非常確定下一個 Token，少數候選就能達到門檻；如果可能的接法很多，就可能需要保留更多候選
